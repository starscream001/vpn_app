# Архитектура

`lib/core/profile.dart`: строгий импорт, стабильный SHA-256 id локального профиля, revision/expiry/revocation, merge и ранжирование.
`storage.dart`: единый версионированный snapshot в OS secure storage, последовательная запись.
`routing.dart`: Xray config, доменные правила и отдельный принудительный VPN inbound для измерений.
`engine.dart`: интерфейс TunnelEngine, Android AWG MethodChannel и Xray plugin; HttpsProbe проверяет HTTPS 204, состояние и прирост счётчиков. DNS используется при HTTPS запросе; отдельный DNS-зонд и доказательство отсутствия утечки DNS пока не реализованы.
`controller.dart`: состояния, сохранение, импорт, API, планировщик, ограничение переключений.
`api.dart`: TLS-only, запрет редиректов с bearer token, ограниченный размер, timeouts, allowlist отчётов, очередь.
`backend/service.py`: отдельный API-пример, не устанавливается на действующие серверы.

## Пути пользователя

1. Первый запуск → открыть защищённое хранилище → добавить сторонний профиль или ввести одноразовый код из бота и адрес HTTPS API.
2. Подключить → не более 4 подходящих кандидатов, по одному → разрешение Android → системный VPN → HTTPS-проверка и RX/TX → только после успеха «Подключено».
3. Ручной выбор профиля/протокола ограничивает перебор. Во время VPN менять маршруты нельзя: сначала отключить.
4. Каждые 30 секунд, пока работает приложение, повторная проверка. 3 сбоя подряд и минимум 2 минуты после переключения → в Авто новая ограниченная попытка с пропуском упавшего профиля. Сон/фон Android не гарантируют работу Dart-таймера.
5. Каталог загружается целиком, проверяется и затем сохраняется. Сетевая ошибка не удаляет прежние профили. Старые revision не заменяют новые. `revoked_ids` удаляет профиль и сохраняет tombstone между запусками: старый каталог не воскресит отозванный ID; повторная выдача требует нового ID. expiresAt запрещает его выбор. Активный истёкший профиль отключается при проверке.
6. Продление в существующем боте → бот проверяет оплату → обновляет entitlement/revision/expiry → клиент обновляет каталог. Текущий код не принимает платежи и не выпускает серверные ключи.
7. Сторонние профили не требуют FoxWay-подписки; они никогда не включаются в отчёты.
8. Телеметрия выключена изначально. Включение сохраняет обезличенные результаты FoxWay в зашифрованную очередь; HTTP-ошибка оставляет события. Выключение очищает очередь. Доставка at-least-once, backend-агрегация должна учитывать возможные дубли.

## Границы

Нельзя определять рабочий VPN только по ping или наличию локального TUN. Текущая проверка сильнее ping, но ещё требует стендового подтверждения на реальных движках. Общий HTTPS ресурс может быть недоступен независимо от VPN; в релизе нужен контролируемый оператором endpoint и резервный probe.

Автоматическое разделение российских сайтов сейчас реализовано только в Xray по домену/sniffing. CDN, ECH и сайты на других доменах требуют явных правил и тестов. AWG передаёт IP-пакеты и не знает домены: IP-списки/отдельный DNS route manager ещё предстоит реализовать. Не делать вид, что одно и то же правило работает во всех движках.

Надёжный kill switch должен обеспечиваться ОС/нативным движком, а не UI-переключателем. В preview есть переход в настройки Android; always-on/lockdown AWG ещё не реализованы. Desktop/iOS VPN отсутствует. После перезапуска процесса UI ещё не восстанавливает состояние уже запущенного native VPN — перед выпуском нужен native event/state reconciliation.

Статистика качества хранится глобально, без сетевого fingerprint. Раздельная история по Wi-Fi/LTE, backoff по сетям, автоматическое обновление сторонних подписок, избранное, QR, deep-link, автозапуск, светлая тема и английский перевод — последующие этапы.

Каталог FoxWay автоматически обновляется каждые 15 минут при активном Dart-процессе; сетевая ошибка сохраняет кэш и откладывает следующую попытку.
